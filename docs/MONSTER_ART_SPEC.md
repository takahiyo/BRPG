# モンスター画像の制作・組込み仕様

ゲームの正本は `DATA.enemies` / `DATA.bosses` と `CATALOG.monsters`。名前から近い画像を推測して割り当てない。ゲームIDが異なる種・属性違い・ボスはそれぞれ別の確認対象とする。

## 発注リスト

`monster-art/manifest.json` はID・名称・シート・セルの対応表。`monster-art/catalog-01.md`〜`catalog-14.md` は図鑑400種、`encounter-01.md`〜`encounter-03.md` は実際の遭遇モンスターの制作リスト。制作時には対象シートの表をそのまま画像生成へ渡す。同名でもゲームIDを保持し、入力順を変えない。セル番号は各シートの1から開始する。現時点で新規画像は未制作、全件 `verified: false`。

## 画像生成へ渡す共通指示

> 西洋ファンタジー図鑑風の精緻な手描き彩色イラスト。添付の表の対象名・固有属性・体形を厳守し、左上から右へ、次の行へ入力順に配置する。横5列×縦6行の30セル。希望寸法2560×3072px、1セル512×512px。各対象は全身を中央76%以内に収め、角・翼・尻尾・武器先端・炎を含めて四辺8%以上の空白を確保する。文字、番号、名称、ロゴ、枠線、仕切り線、風景、床、地面、接地影、台座、羊皮紙、光輪、後付けの称号エフェクトを描かない。柔らかな左上光、自然な落ち着いた色、正面から少し斜めの3/4ビュー。小さなサムネイルでも種族の特徴を区別できる形にする。未使用セルは空白。

- 出力は **実際のアルファ透明PNG**。生成時に `transparent_background: true` を指定。透明を示す市松模様を描かない。アルファが存在するだけでなく、余白が透明なピクセルであることを確認する。
- 透明出力が使えない場合は全面単色 **#202C2C**（通常戦闘カード背景）。その出力は非透明・未承認として扱い、背景除去してから組み込む。選択中カード背景は **#35392E**、図鑑カードは **#1C251E**、ページ背景は **#111714**。単色画像をそのまま複数の背景へ使わない。
- 旧画像は5列×8行、名前・枠・紙背景が焼き込まれている。新規5列×6行への流用不可。旧番号と新セル番号を混同しない。

## 検品とゲーム側の接続

1. シートの寸法・5×6配置、全身・安全余白、透明背景、名前との一致、欠落・重複・隣セルへの侵入をリストと照合する。
2. モンスターの名称に含まれる特徴を確認する。例：炎のトカゲを一般トカゲ、ミイラをゾンビ、溺死者をゾンビに置き換えない。属性違いの狼を通常狼で代用しない。
3. 確認できたセルのみ `verified: true` にし、`systems.js` の `BRPGMonsterArt.sheets` に `{ src, columns: 5, rows: 6 }`、`cells[ゲームID]` に `{ sheet, cell, name, verified: true }` を登録する。
4. `scripts/build-pages.cjs` の配布許可リストへ実ファイルを追加する。スプライトの位置・背景サイズは登録寸法から計算する。図鑑番号を旧シート位置に自動変換する処理や、名前の類似による代用は禁止。
5. 通常・選択・図鑑の3背景で四角い余白や文字が出ないこと、64px以下でも識別できることを実画面で確認する。未確認セルは種別アイコンを使う。

## 現在の修正

旧シートを目視すると、旧対応表の `firelizard → 大トカゲ`、`mummy/drowned → ゾンビ`、`frostwolf → ダイアウルフ` などに誤対応があり、シート2の参照ファイルも存在しなかった。誤った絵と背景枠を表示しないよう旧推測表を外し、検品済み画像の明示登録方式へ変更した。新しい完成画像の制作・検品はこの仕様と入力リストを使用する。
