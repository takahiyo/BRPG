# モンスター画像の制作・組込み仕様

ゲームの正本は `DATA.enemies` / `DATA.bosses` と `CATALOG.monsters`。名前から近い画像を推測して割り当てない。ゲームIDが異なる種・属性違い・ボスはそれぞれ別の確認対象とする。

## 発注リスト

`monster-art/manifest.json` はID・名称・シート・セルの制作予定対応表。`monster-art/catalog-01.md`〜`catalog-14.md` は図鑑400種、`encounter-01.md`〜`encounter-03.md` は実際の遭遇モンスターの制作リスト。制作時には対象シートの表をそのまま画像生成へ渡す。同名でもゲームIDを保持し、入力順を変えない。セル番号は各シートの1から開始する。均等グリッドとしての一括承認はしておらず、この制作manifestは全件 `verified: false`。

現在の実装は [検品記録](MONSTER_ART_INTEGRATION.md) の21体を `monster-art.js` の明示的な実ピクセル矩形で登録する。制作段階の均等セルmanifestは全件未承認のままであり、実際の矩形承認と混同しない。全14原本はゲーム内の「制作シートを確認」で未検品を含む旨を表示して閲覧できる。個別表示の残り379種と遭遇専用70種は未登録。

[フレーバー付き制作表の索引](MONSTER_ART_TABLES.md) から全17シートを開ける。各表に種族/特性または制作用の外見補助、生態/生息地、フレーバーを併記した。現行ゲーム用はencounter-01〜03を優先し、図鑑400種とは別画像として制作する。背景に関するフレーバーは雰囲気の参考であり、背景を描く指示ではない。`python scripts/export_monster_art_tables.py` で既存manifestの対応を変えずに再生成できる。

## 画像生成へ渡す共通指示

現在の画風参照：[受領シート02](../monsters_sheet02_M0031-M0060.png)。基準実寸は **1145×1374px（RGBA PNG）**、幅/5・高さ/6とも **229px**。これは受領画像に基づく制作基準であり、ChatGPTの全モデル・全設定に共通の上限とは断定しない。寸法の一致だけでは均等配置や透明余白を保証しない。元画像は加工せず保持し、ゲームへの自動登録はしない。

受領14枚はプロジェクト直下へ `monsters_sheetNN_Mxxxx-Myyyy.png` 形式で移動済み。通常版は02〜14、14の横長別案は `_alt.png`。削除された旧参考画像はユーザー指定で復元せず、01は欠番として扱う。元名・移動先・実寸・保全ハッシュ・要検品点は [受領シート整理記録](monster-art/RECEIVED_SHEETS.md) を参照。07/10の高さ不足と14の配置違いは未補正。

下記の共通指示と制作表1シート分を渡す。参考画像を添付できる場合は画風・形の密度の参考として添える。持ち運び用の詳細指示は [アセットシート共通プロンプト](monsters/アセットシート共通プロンプト.md)。

> 添付サンプルのような西洋ファンタジー図鑑風の手描き彩色で、今回の制作表だけを描く。サンプルの個体・種の並びを複製せず、表の対象名・固有属性・体形を優先する。横5列×縦6行の30セル、基準1145×1374px、1セル229×229px。大きなキャンバスへの拡大出力は要求しない。左上から右へ、次の行へ入力順に、1セルに1対象を配置する。全身・角・翼・尻尾・武器を中央約174px以内に収め、不可欠な炎も含めて四辺19px以上を完全な透明にする。必要ならポーズを畳み、全体を小さくして収める。細かな模様を詰め込むより、64px表示でも分かる顔・体形・固有属性を優先する。文字、番号、名称、ロゴ、枠線、仕切り線、風景、床、地面、接地影、台座、羊皮紙、後付けの光輪を描かない。柔らかな左上光、落ち着いた自然色、正面から少し斜めの3/4ビュー。参考画像の密集・切れ・輪郭外の色にじみを引き継がず、隣セルへ一切侵入しない。未使用セルは透明のまま。フレーバー中の景色は背景に描かない。出力は実アルファ透明PNGで、市松模様を描かない。

- サイズを直接指定できない場合は、同等以下のサイズで5:6を優先し、生成後の実寸を必ず記録する。比率が異なる出力は余白調整・再配置を別工程で行い、機械的に正方形セルとして切り出さない。非等方の引き伸ばしで比率を合わせない。
- 出力は **実際のアルファ透明PNG**。ChatGPTの画面では透明背景での出力を依頼し、API利用時は提供元の正式な透明出力オプションを使う。アルファが存在するだけでなく、余白が透明なピクセルであることを確認する。
- 透明出力が使えない場合だけ全面単色 **#E8E8E8**（共通プロンプトと同じ中立灰色）。非透明・未承認として背景除去を別工程で行う。通常戦闘カード **#202C2C**、選択中 **#35392E**、図鑑 **#1C251E**、ページ **#111714** と明色背景で縁を確認し、単色画像をそのまま使わない。
- 旧画像は5列×8行、名前・枠・紙背景が焼き込まれている。新規5列×6行への流用不可。旧番号と新セル番号を混同しない。

## 検品とゲーム側の接続

1. 実寸と5×6配置を記録する。1145×1374pxなら229px単位で切り出し、全身・四辺19px以上の透明余白、名前との一致、欠落・重複・隣セルへの侵入を照合する。30体が並んでいるだけで厳密な切出しを承認しない。
2. モンスターの名称に含まれる特徴を確認する。例：炎のトカゲを一般トカゲ、ミイラをゾンビ、溺死者をゾンビに置き換えない。属性違いの狼を通常狼で代用しない。
3. 確認できた対象のみ `monster-art.js` から `BRPGMonsterArt.sheets` に `{ src, width, height }`、`cells[ゲームID]` に `{ sheet, rect: { x, y, width, height }, name, verified: true }` を登録する。矩形は実ピクセル、全身と隣接混入を検品し、制作manifestの均等枠から自動計算しない。
4. `scripts/build-pages.cjs` の配布許可リストへ実ファイルを追加する（受領14原本は追加済み）。SVGの矩形クリップと縦横比保持で表示する。図鑑番号を旧シート位置に自動変換する処理や、名前の類似による代用は禁止。
5. 通常・選択・図鑑の3背景で四角い余白や文字が出ないこと、64px以下でも識別できることを実画面で確認する。未確認セルは種別アイコンを使う。

## 現在の修正

旧シートを目視すると、旧対応表の `firelizard → 大トカゲ`、`mummy/drowned → ゾンビ`、`frostwolf → ダイアウルフ` などに誤対応があり、シート2の参照ファイルも存在しなかった。誤った絵と背景枠を表示しないよう旧推測表を外し、検品済み画像の明示登録方式へ変更した。新しい完成画像の制作・検品はこの仕様と入力リストを使用する。
